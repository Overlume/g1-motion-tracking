A = 原奖励（weight 0.5 / std 0.3）；B = 只把 `motion_global_root_pos` 的 weight 改到 1.5，std 保持 0.3。**唯一变量：一行 weight。**

## 1. 目的与事前假设

LAB05 同时改了 weight（0.5 -> 1.0）与 std（0.3 -> 0.15），B 组更差（root 误差 43.34 -> 52.72 cm）。`docs/DECISIONS.md` 的 D13 给了一个机制解释——"std 收窄把奖励核的作用域掐死了"——但那是解释，不是证据。本 run 补上缺的那一半对照：只动 weight，std 一动不动。

登记的三个假设（用户在 2026-11-16 选方案 A 时写下）：
- **H1 核宽塌缩**：std 才是元凶，只加权重会有 5–15% 以上的收益。
- **H2 观测缺失**：policy 看不到自己的世界位置，改奖励没用（A/B 差异 < 3%）。
- **H3 权重过载**：root 略好，但 R-MPKPE / joint_rmse 退化（用姿态换位置）。

## 5. 机制：为什么"只加两倍权重"能好 38%

奖励核是 `exp(-d²/std²)`（repos/mjlab_research/src/mjlab/tasks/tracking/mdp/rewards.py:26-33），对误差 d 的梯度幅值是 `(2d/std²)·exp(-d²/std²)`，权重再乘上去：

| 误差 d | A: w0.5/std0.3 | LAB05-B: w1.0/std0.15 | LAB06-B: w1.5/std0.3 |
| --- | --- | --- | --- |
| 0.20 m | 1.42 | 3.00 | 4.27 |
| 0.45 m | 0.52 | **0.0049** | 1.57 |

std=0.15 时核在 d≈0.3 m 外基本归零：LAB05-B 在 0.45 m 处的梯度只有 A 的 1/100，权重加倍完全补不回来。所以它不是"更严格"，而是**在真正需要拉回的区间里没有信号**。反观 std 保持 0.3、权重 x3，整个 0.2–0.5 m 区间的梯度都跟着放大，效果立刻出现。

## 7. 局限（写报告时必须带上）

1. **训练集 = 评估集**：S3 既用于训练也用于评估，本结论只对这个片段成立，不能外推到未见动作。
2. **300 iter 只有官方预算的 0.6%**：这是"能走起来"的尺度，不是收敛尺度；权重的最优点可能随训练变长而移动。
3. **weight 只有 0.5 / 1.5 两个点**：不知道 2.5 会不会更好，边际递减点未测。
4. **训练侧单 seed 单次**：只有评估侧量化了噪声底（≈4%），训练侧没有。
5. **代价真实存在但小**：tilt 误差 +14%、左脚滑移 +25%、joint_vel_rmse +5%，不能只说"全面变好"。
6. anchor_pos 终止计数与误差反向变动，未解释。

## 8. 附：为什么 B 组日志里的 Iteration time 是负数

不是训练异常，是本机 WSL2 的实时钟在跳（记为 D14）：

- `environment/.venv/lib/python3.13/site-packages/rsl_rl/runners/on_policy_runner.py` 第 81 行取 `start = time.time()`，第 101–103 行算 collect、第 111–112 行算 learn，全程用**墙上时钟**差分。时钟被往回拨，差值就是负的。
- 本机实测（2026-11-16 17:01 空闲状态下）：monotonic 窗口 15.07 s 里 `time.time()` 只走了 13.55 s，期间 6 次跳变，幅度 **+7.43 / -7.94 s**，周期约 5.5 s；`journalctl` 里 systemd-resolved 一直在打印 "Clock change detected. Flushing caches."（没在训练时也在打印）。
- `/proc/uptime` 与 perf_counter 同步（10 s 窗口内都是 10.03 s），说明单调时钟没问题，只有 CLOCK_REALTIME 在跳。
- 影响面：Iteration time / Time elapsed / ETA / 脚本用 `date` 记的墙钟都偏小约 10%（所以这 638/650 s 实际约 710 s）；**训练数学、ckpt、评估指标不受影响**。
- 处置：报告脚本已剔除非正值并在表里列出负值样本数；今后计时以 `perf_counter` / `/proc/uptime` 为准；跨会话只比相对值。
- 修复建议（需要你的 sudo 密码，我执行不了）：`sudo hwclock -s` 立即对齐，再 `sudo timedatectl set-ntp false` 关掉 guest NTP（WSL2 官方建议时间由 Windows 主机管）。
