- 目的：回答 M4 的问题——300 iter 的 25.72 cm 是“训练不够”还是“配置到顶”。
- 两臂：300 iter = `runs/20261116-002-lab06-b-finetune/model_50298.pt`；3000 iter = `runs/20261117-001-m4-w15-finetune/model_52998.pt`（4096 env、seed 0、从 scratch/model_49999.pt 续训）。
- 动作：`data/processed/fight1_s3_000s_20s.npz`（sha256 965f2c4b…66c66）；评估：`scripts/eval_tracking.py`，种子 101–105，终止检测开、启动 DR 关，跑满 999 步（19.98 s）。

五个种子的分布完全不重叠（300 臂最差 26.47 > 3000 臂最差… 即 300 臂最好 24.63 远大于 3000 臂最差 4.12），远超 4% 噪声底。

## 假设判定

- **H1（预算不足）成立**：root 误差 −84.8%，远超“>20%”的判据。
- **H2（配置到顶）否**：25.72 cm 不是这套配置的地板，300 iter 只是没收敛。
- **H3（过拟合/退化）否**：R-MPKPE、joint_rmse、joint_vel_rmse、yaw、滑移全部同向变好，只有 tilt 在噪声内。位置与姿态这次没有互相付钱。

## “3.90 cm 可信吗”：两条独立校验

1. **不是积分漂移**：seed101 的 root 误差随时间是振荡（0.15 → 5.08 → 7.34 → 1.10 → 8.86 → 1.87 … cm），段内线性拟合斜率 −0.07 cm/s，末端回到 0.0 cm。若是指令/观测坐标系有错位，误差应单调累积，而这里没有。
2. **姿态也同步变好**：R-MPKPE 从 6.10 降到 3.66（官方预训练在 dance1 上是 3.42），MPKPE 5.64。位置对了但姿态不对的“假对齐”不会出现这种全线改善。

## 但它是“这个片段的专家”，不是“会跟踪”——泛化探针（探索性，n=1）

同一 ckpt（model_52998）换到训练时没见过的片段上评估（seed 101，`runs/20261117-003-generalization-probe/`）：

| 评估片段 | 完成度 | reset 次数 | root 误差 cm | 最长存活段 |
| --- | --- | --- | --- | --- |
| 训练片段 S3 000–20 s | 0.999 | 1（motion_end） | 3.98 | 19.96 s |
| 同片段未见窗口 S3 120–140 s | 0.101 | 24（全为 ee_body_pos） | 12.70 | 2.02 s |
| 未见片段 S2 134 s | 0.024 | 50（全为 ee_body_pos） | 14.66 | 0.48 s |
| 官方 model_49999，同上 S3 120–140 s | 0.016 | 70（全为 ee_body_pos） | 3.06† | 0.32 s |

† 官方那一行的 root 误差不可比：它每 0.3 s 就被重置一次，几乎没走出片头，误差自然小。**reset 频繁时 root 误差无意义，只看完成度与存活段**。

所以准确的表述是：**3000 iter × 单一 20 s 片段 = 把通用策略特化成了该片段的回放器**。它在训练片段上 0 摔、3.90 cm；一旦换片段，0.3–2 s 内就触发 `ee_body_pos` 终止。这符合“295 M env-steps ≈ 该 20 s 片段被重复播放 29 万遍”的直觉，也与 D11 的“只报分布”原则一起说明：**这个数字必须标注 in-distribution**。

## 口径：为什么训练侧 error_anchor_pos 只从 0.131 降到 0.114

| | 训练侧 `Metrics/motion/error_anchor_pos` | 评估侧 `root_err_cm` |
| --- | --- | --- |
| 距离 | 3D 范数（含垂直 z），见 `repos/mjlab_research/src/mjlab/tasks/tracking/mdp/commands.py:306` | 只取 xy |
| 时刻 | 每个迭代在 4096 个 env、随机抽帧上取平均，含 reset 后瞬态 | 单条确定性 rollout，从第 0 帧起 |
| 动作 | 训练用带噪声的采样动作（std ≈ 0.9） | 评估用均值动作 |
| 结果 | 0.1141 m | 0.0390 m |

同一套策略在两个口径下差 3 倍属正常，**不能用一个去校验另一个**。要对比就必须同口径。

## 用户预测判分（docs/learning/LAB08-prediction.md）

- **Q1（root → 约 10 cm）**：方向对、幅度保守。实测 3.90 cm，比预测好 2.5 倍。你用的“迭代 ×10 → 误差减半”是经验规律，实测是 ÷6.6。**结论**：单调下降的趋势判断正确，指数级的量级判断偏保守。
- **Q2（R-MPKPE 变差）**：**错**。实测 6.10 → 3.66（−40%）。机制：300 iter 时策略离收敛还很远，姿态项（motion_body_pos/ori 权重 1.0）根本没被压下去；加预算让所有奖励项一起变好，不存在“位置吃姿态”的此消彼长。你的推理在“已经收敛后继续加权重”的场景才成立（LAB07 的 w2.5 就是这个场景）。
- **Q3（error_anchor_pos → 0.05）**：数值偏乐观（实测 0.114），但你在括号里承认“不清楚两者差在哪”——这正是要点：它们不是同一个量（见上表口径）。
- **Q4（下一步改 std）**：**前提错了**——这次实验恰恰证明“训练迭代次数是瓶颈”。不过你的排查链（硬件 / 数据 / 策略，并否定“为单个动作改机器人参数”）方向是对的，这题本身没有标准答案。

## 局限（必须随数字一起引用）

1. **训练集 = 评估集**：同一个 20 s 片段、同一个起点。3.90 cm 是 in-distribution 指标。
2. 训练只跑了 **1 个 seed**（seed 0），训练侧方差未量化；评估侧 5 个种子分布很紧（3.79–4.12）。
3. 泛化探针是 **n=1 探索**，尚未按 5 种子正式化（见下一步）。
4. 评估从第 0 帧开始，未测“中途起播”；终止阈值 `ee_body_pos` 较紧，跨片段时最先触发。
5. 温度中位 86 ℃、峰值 88 ℃（GPU 采样 1265 点），接近 RTX 3060 Laptop 的降频线，迭代耗时 1.99 s/iter 可能被散热拖慢；但本实验比较的是不同预算，不是耗时。

## 一句话

预算轴确实是瓶颈，但它买到的是**特化**而不是**泛化**：300 → 3000 iter 把训练片段上的 root 误差压到 3.90 cm 且 0 摔，代价是换片段 0.3–2 s 内必挂。
