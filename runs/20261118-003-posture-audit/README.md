# 20261118-003 M5 姿态审计（零 GPU）：终止的格子到底倒了没有

## 目的

M5 的 12 格粗扫（60 次）+ +y 细化 4 档（20 次）一共 80 次评估，报告里的"终止"一直被当作"失稳/倒地"的证据，但 `fall_detected` 全是 False（只认平躺），而视频核对只看了 4 例。本 run 只用已有的 `metrics.csv`，把 80 次 rollout 按**复位瞬间的姿态**重新分类，回答：终止的格子里，多少是真的姿态崩了，多少是站着被误差阈值判罚。

不跑仿真、不用 GPU，只读日志。

## 输入

| run | rollout 数 | 内容 |
| --- | --- | --- |
| `runs/20261117-005-m5-perturb` | 60 | 4 方向 × 30/60/120 N·s × 5 种子 |
| `runs/20261118-001-m5-threshold-refine` | 20 | +y 的 15/20/25/27 N·s × 5 种子（30 N·s 已含在粗扫里）|
| 合计 | 80 | 均为 `model_52998`、S3 片段、终止检测开、DR 关 |

## 口径

- 每个 rollout 只取**第一次 reset 之前**的帧（复位之后是新回合，不能用）。
- `end_drop` = 复位前最后 0.4 s 内 `ref_pelvis_z - pelvis_z` 的均值（骨盆比参考低多少）。
- `end_tiltex` = 同一窗口内 `tilt_deg - ref_tilt_deg` 的均值（比参考歪多少度）。
- 分类：
  - `survived`：第一次 reset 的项只有 `motion_end`（跑完动作）。
  - `collapse`：提前 reset，且 `end_drop >= 0.08 m` 或 `end_tiltex >= 13 deg` —— 复位瞬间姿态已明显偏离参考。
  - `upright_trip`：提前 reset，但两项都没到 —— 复位瞬间还站得住，属于误差判罚，**之后会不会倒未知**。
- 阈值来源：录像核对过的 4 例（py_j30_s101、py_j60_s101、py_j27_s103 真倒；py_j27_s101 撑住）给出的分界是"末段骨盆低 ≥ 0.10 m 或歪 ≥ 14°"与"末段骨盆低 ≤ 0.003 m 且歪 ≤ 3.8°"两团；取中间值 0.08 m / 13° 作操作阈值。脚本每次运行都会用这 4 例自检，不一致就返回非零。

## 结论

1. **"终止"不是一个东西，至少三类**：跑完（39）、姿态崩（10）、站着被误差判罚（31）。把 41 次提前终止一律写成"失稳/倒地"，会高估失败程度。
2. **本样本里真正的姿态崩只出现在 +y**：27 N·s（0.81 m/s）1/5、30 N·s（0.90 m/s）4/5、60 N·s（1.80 m/s）5/5。+y 的两级阈值可以改写成"**0.75 m/s 起跟踪崩但不倒；0.81 m/s 起出现倒地；0.90 m/s 多数倒地；1.80 m/s 全部倒地**"。
3. **其余方向的 60–120 N·s 终止全是 `upright_trip`**：推后 0.14–0.30 s 就复位，那时骨盆高度与倾角都还在参考附近（末段 Δ 骨盆 −3.2 ~ +5.5 cm、Δ 倾角 1.5°–11.4°）。这类终止说明"位移/指尖误差超阈值"，**不说明机器人倒没倒**，回合在那里结束，结局未知。
4. 所以 M5 的"+y 最脆弱、+x 最抗推"排序仍成立，但含义要精确：**+y 是唯一把"终止"变成"真倒"的方向**；其他方向比的是"多快被误差阈值判罚"。
5. D20 修订仍不充分：`fall_detected` 只认平躺是问题之一，更关键的是**终止时刻早于倒地**，用终止当倒地代理会系统性高估失败。

## 局限

1. 阈值 8 cm / 13° 来自 4 例录像，样本小；边界敏感区很窄（+y 60 的 14.7°–16.8° 与 `upright_trip` 的 11.4° 只差 3°）。
2. 末段窗口 0.4 s（20 帧），噪声不小；结论用中位 + 逐次明细，不靠单点。
3. `upright_trip` 的"结局未知"是实质限制：要回答"推完 3 s 内会不会倒"，必须跑 `--ignore-terminations` 的恢复实验，本 run 做不到。
4. 分类不区分 `anchor_pos` 与 `ee_body_pos` 两类终止项。

## 下一步

M5 剩下的问题不是"阈值在哪"，而是"**被判罚的那些回合，如果允许它继续，会不会倒、能不能恢复**"。需要把评估改成 `--ignore-terminations` 跑推后 3 s 的恢复段，覆盖当前 6 个全 `upright_trip` 的格（+x 120、−x 60、−x 120、+y 120、−y 60、−y 120，30 次评估约 20 min），再用同一套姿态判据打分。
